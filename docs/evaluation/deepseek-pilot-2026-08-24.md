## 失败证据

最终错误为开发返工计划引用了未知需求编号：

    ValueError: developer plan references unknown requirements:
    {'REV-003', 'REV-004', 'REV-005'}

这些编号实际来自 Reviewer 的问题列表，不是 PRD 的 FR/NFR 需求编号。除此之外，Developer 在 STANDARD 治理等级下已经从 STRONG 开始，旧路由仍把第二个 STRONG 作为“升档”，没有获得更强模型能力，却再次消耗完整请求窗口。

## 已落地修复

1. 路由计划到达 STRONG 后停止追加相同档位，保证“升档”一定意味着能力档位实际变化。
2. Developer 读取历次结构化反馈中的 issues[].requirement_ids，把 REV-*、测试或其他反馈问题编号映射回真实 FR/NFR。
3. 映射只能使用产物里可证明的追踪关系；没有合法关联需求的问题编号仍由严格校验拒绝，不能静默绑定到任意需求。
4. 为上述两个缺陷增加单元/集成回归测试。

## 后续实验要求

在报告动态路由优劣前，至少需要：

- 使用同一代码版本、模型版本和场景分别运行 DYNAMIC 与固定档策略；
- 每种策略至少重复三轮；
- 分别报告完成率、门禁通过率、Token、模型耗时和墙钟耗时；
- 将网络/格式错误、代码质量失败和运行环境失败分开统计。
